# План: единый каталог героев

## Цель

Создать один машиночитаемый файл с полной карточкой каждого героя и защитить его от рассинхронизации с gameplay-кодом и animation pipeline.

## Решение

- `docs/hero-catalog.json` — каталог героев: identity, gameplay-параметры, способности, анимации, ассеты и источники.
- `docs/hero-catalog-maintenance.md` — обязательная инструкция для ИИ и разработчиков.
- `tools/validate_hero_catalog.py` — read-only проверка каталога против `heroes.go`, `attack_config.go` и Blender manifest.
- `frontend/package.json` — команда `npm run validate:hero-catalog` для запуска проверки из frontend.

## Критерии приёмки

- [ ] В каталоге присутствуют все текущие герои, способности и runtime-анимации.
- [ ] Валидатор ловит добавление/удаление героя, изменение gameplay-параметров, изменение attack-конфига и изменение списка анимаций.
- [ ] В документации явно сказано: любое изменение героя начинается с обновления каталога, после чего ИИ синхронизирует зеркала.
- [ ] Проверка запускается одной командой и завершается ненулевым кодом при рассинхронизации.

## Риски

- Часть данных остаётся narrative-описанием и не может быть надёжно выведена из Go автоматически. Для таких полей валидатор требует ручного обновления `lastReviewed` и источников.
- Blender-файлы тяжёлые и не должны читаться валидатором; проверяется их versioned manifest.
