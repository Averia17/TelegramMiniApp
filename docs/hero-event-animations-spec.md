# Канонический Hero GLB

## Решение

Игра загружает ровно один gameplay GLB для каждого героя. Этот файл является
единственным runtime-источником модели, скелета, экипировки и всех анимаций.
Перенос `AnimationClip` между разными GLB больше не используется.

```text
frontend/public/assets/heroes/output_heroes/<hero>_base.glb
  HeroRoot
    Armature
      ...bones
      hand/wrist
        Socket.Weapon.L или Socket.Weapon.R
          held weapon
    meshes
    AnimationClips
      idle run hit death super Aim AimSuper Attack Spawn Victory
```

Исходные `.blend`, FBX и раздельные actions могут храниться отдельно. Их
раздельность заканчивается на build-этапе: результатом экспорта всегда является
самодостаточный Hero GLB.

## Контракт скелета и экипировки

- Сокеты оружия называются `Socket.Weapon.L` и `Socket.Weapon.R`.
- Сокет является непосредственным ребёнком соответствующей кости кисти или
  запястья.
- Жёсткое удерживаемое оружие является ребёнком сокета и получает
  `attachment_role = "held-weapon"`.
- Бросаемое оружие до момента release является ребёнком сокета и получает
  `attachment_role = "throwable-weapon"`.
- Независимые companion/VFX-объекты могут использовать отдельные роли, например
  `attack-cloud`; они не считаются оружием в руке.
- Оружию не нужен собственный animation track, если оно должно только следовать
  за рукой. Трансформация наследуется от анимируемой кости через сокет.
- У составного или деформируемого оружия может быть собственный rig, но его
  корень всё равно находится под сокетом героя.

Для двуручного оружия владелец всегда один сокет. Вторая кисть следует за точкой
дополнительного хвата с помощью IK во время авторинга; объект нельзя одновременно
parent-ить к двум рукам.

## Runtime

`AssetRegistry` загружает и кеширует только `<hero>.glb`, клонирует его через
`SkeletonUtils.clone` и передаёт встроенные clips одному `AnimationMixer`.

Отдельные `animations/*.glb` не публикуются и не запрашиваются. Это исключает
неявную совместимость по именам костей и ситуацию, когда clip принадлежит одному
графу сцены, а оружие — другому.

## Проверка перед публикацией

```powershell
cd frontend
npm run validate:heroes
npm test
npm run lint
npm run build
```

`validate:heroes` проверяет:

- наличие всех десяти clips;
- именованные animation targets;
- размещение weapon sockets под кистями;
- канонические роли оборудования;
- размещение удерживаемого оружия непосредственно под socket.

Экспорт считается неуспешным, если хотя бы один из этих инвариантов нарушен.

## Специальные случаи

- Brock Zeus не имеет полноценного humanoid arm rig; его облако остаётся
  независимым `attack-cloud`.
- Needle и Fairy Mina пока создают удерживаемый projectile visual в runtime, но
  он присоединяется к каноническому правому socket, когда socket доступен.
  Projectile после release остаётся отдельной gameplay-сущностью.
