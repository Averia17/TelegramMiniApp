# Спецификация: отдельные анимации событий героев

## Цель

Перевести героев на событийную систему авторских Blender-анимаций. Атака должна
выглядеть как осмысленная атака конкретного героя, а появление — как полноценный
выход героя на арену. Рантайм только выбирает и воспроизводит нужную анимацию,
не подменяя её процедурными поворотами костей, масштабированием или подпрыгиванием.

## Принятые допущения

1. Модель, скелет, материалы и визуальная экипировка каждого героя остаются
   совместимыми между всеми файлами этого героя.
2. У каждого героя будет базовый файл модели и отдельный Blender-файл для каждого
   клипа: `idle`, `run`, `aim`, `aimSuper`, `attack`, `super`, `spawn`, `victory`,
   `defeat`.
3. Для веб-рантайма каждый событийный Blender-файл экспортируется в отдельный GLB:
   `attack.glb`, `spawn.glb`. Базовый GLB продолжает содержать модель и циклические
   состояния (`idle`, `run`, `aim`, `aimSuper`).
4. Событийный GLB содержит совместимый скелет и ровно один клип с каноническим
   именем (`Attack` или `Spawn`). Рантайм переносит этот клип на экземпляр героя
   и воспроизводит его через единственный `AnimationMixer`.
5. `Attack` и `Spawn` проигрываются один раз. После завершения герой плавно
   возвращается в `Idle`, `Run` или `Aim` согласно текущему состоянию игры.
6. Существующие незакоммиченные изменения не удаляются и не перезаписываются
   без необходимости.

## Технический стек и команды

- Blender Python (`bpy`) — подготовка `.blend` и экспорт `.glb`.
- three.js `0.180.0`, `GLTFLoader`, `AnimationMixer` — загрузка и воспроизведение.
- Сборка: `cd frontend && npm run build`
- Тесты: `cd frontend && npm test`
- Линт: `cd frontend && npm run lint`

## Структура

```text
frontend/assets-source/heroes/<hero>/
  <hero>.blend
  animations/
    attack.blend
    spawn.blend

frontend/public/assets/heroes/<hero>/
  <hero>.glb
  animations/
    attack.glb
    spawn.glb

frontend/src/components/BattleGame/rendering/
  assets/          манифест и загрузка базовых/событийных ассетов
  heroes/          событийный контроллер AnimationMixer
```

## Контракт кода

```js
animations: {
  attack: {url: "/assets/heroes/mandy/animations/attack.glb", clip: "Attack"},
  spawn: {url: "/assets/heroes/mandy/animations/spawn.glb", clip: "Spawn"},
}
```

Событие определяется изменением серверного pulse (`attackPulse`, `spawnPulse`).
Повтор одного значения не перезапускает клип. Новое значение перезапускает
одноразовый клип с начала.

## Стратегия тестирования

- Unit: манифест каждого героя содержит отдельные URL для `attack` и `spawn`.
- Unit: реестр загружает и кеширует событийные клипы отдельно от базовой модели.
- Unit: изменение pulse запускает соответствующий клип ровно один раз.
- Unit: завершившийся клип освобождает overlay и возвращает locomotion.
- Unit: отсутствие событийного файла не ломает героя; используется безопасный
  fallback без процедурной имитации атаки.
- Asset validation: каждый GLB содержит ровно ожидаемый клип и совместимые имена
  костей.
- Runtime: тестовый harness визуально проверяет `attack` и `spawn` каждого героя.

## Границы

- Всегда: сохранять совместимость скелета, проверять клипы после экспорта,
  запускать тесты и production build.
- Сначала согласовать: изменение набора героев, добавление новых событий сверх
  текущего списка, замена исходной модели или рига.
- Никогда: удалять пользовательские правки, скрывать ошибки загрузки, смешивать
  авторскую атаку со второй процедурной позой костей.

## Критерии готовности

1. У каждого доступного героя существуют отдельные `.blend` и `.glb` для всех
   девяти клипов.
2. `Attack` визуально содержит подготовку, удар/выпуск снаряда и восстановление.
3. `Spawn` визуально содержит появление, выразительный акцент и устойчивую
   финальную стойку.
4. Игра вызывает клипы по `attackPulse` и `spawnPulse`, не по таймерной догадке.
5. После одноразового клипа корректно продолжается текущее locomotion-состояние.
6. Процедурная подмена attack/spawn удалена из пути, где доступен авторский клип.
7. Тесты, линт и сборка проходят.

## Открытый вопрос

Следует подтвердить формат: отдельный `.blend` и отдельный `.glb` на событие
для каждого героя. После подтверждения первым вертикальным срезом будут Mandy
(`attack` + `spawn`) и полный путь от Blender до игрового события; затем тот же
контракт будет распространён на остальных героев.
